# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it responsibly:

1. **Do not** file a public GitHub issue for sensitive security vulnerabilities.
2. Use GitHub's private vulnerability reporting feature — this is the only supported
   channel and it reaches the maintainer (@Mr-Nobody-Anonymous) directly:
   - Open <https://github.com/Mr-Nobody-Anonymous/arena-ai-android/security/advisories/new>,
     or navigate to the **Security** tab of the repository and click **Report a vulnerability**.
   - Do not open a public issue for a vulnerability, and do not send reports to Arena/LMSYS:
     they do not maintain this client.
3. Include details of the vulnerability:
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if known)
4. We will acknowledge receipt of the report within 48 hours and work on a prompt remediation release.

## Security Architecture & Best Practices

- **Minimal, Explicit Permissions:** The app declares exactly `android.permission.INTERNET` and `android.permission.REQUEST_INSTALL_PACKAGES` (self-updates only). No location, camera, audio, or storage permissions are declared. Camera capture is performed by the user's camera app and returned through a single-use `FileProvider` URI.
- **Backup Disabled:** `android:allowBackup="false"` is enforced to protect private authentication tokens and cookies from unauthenticated device extraction via `adb backup`.
- **Cleartext Traffic Disabled:** `android:usesCleartextTraffic="false"` blocks all non-HTTPS network requests at the OS level.
- **Local File Scheme Restrictions:** `setAllowFileAccess(false)`, `setAllowContentAccess(false)`, `setAllowFileAccessFromFileURLs(false)`, and `setAllowUniversalAccessFromFileURLs(false)` prevent web content from probing the device file system.
- **Origin Isolation & Navigation Allow-List:** Embedded WebViews are strictly restricted via navigation allow-listing to approved Arena domains (`arena.ai`, `lmarena.ai`) and trusted OAuth endpoints. Outside links open in the system browser via `Intent.ACTION_VIEW`.
- **Cryptographic Signing & Integrity:** Release builds enable APK Signature Schemes v1, v2 and v3 and are verified with 4-byte zip alignment (`zipalign`) plus `apksigner verify --print-certs` on every CI run (`scripts/verify-apk.sh`). The release key is supplied through protected GitHub Actions secrets; CI never generates one.
- **Verified Self-Updates:** Downloaded updates must match the published SHA-256, carry the `ai.arena.mobile` package name, not downgrade the version code, and be signed by the same certificate as the installed app. Failing any check deletes the file and refuses to open the installer.
- **Failed Update Downloads Are Deleted:** Interrupted, cancelled or unverifiable downloads are removed from the private cache.

## Release Key Policy

- The release keystore and its passwords are stored only in GitHub Actions secrets and in the maintainers' secure storage. They are never committed, printed, or generated by CI.
- `android/app/build.gradle` reads `ARENA_RELEASE_STORE_FILE`, `ARENA_RELEASE_STORE_PASSWORD`, `ARENA_RELEASE_KEY_ALIAS` and `ARENA_RELEASE_KEY_PASSWORD`. If they are missing, the build prints a warning and falls back to the debug key; `.github/workflows/release.yml` refuses to publish in that case.
- The signing certificate fingerprints are published in the README and must be updated whenever the key rotates.
